# local-kb-engine

**当前状态：仅规划，尚未实现。**

本仓库目前只有这份说明。下文是个人本地知识库引擎的目标设计与 14 天开发排期，不代表任何服务、命令、解析器、检索链路、测试或自动化已经存在。阅读时请把所有流程都视为计划，而不是已完成能力。

## 项目简介

local-kb-engine 计划做成一个个人本地知识库引擎：

- 向量化使用本地向量模型 Qwen3-embedding。
- 服务层使用 FastAPI。
- 操作入口使用 CLI。
- 架构为 FastAPI + CLI。

知识库与向量计算都计划留在本机。上述模型、服务和命令行都还没有实现。

## 核心处理管道

以下管道是计划中的处理顺序。仓库里没有对应代码、队列或状态存储。

### PDF 分级解析

1. 使用 PyMuPDF 预检，区分空页与扫描页。
2. 将待处理页面送入异步队列。
3. 纯文扫描件交给 RapidOCR。
4. 复杂排版、表格和公式交给 MinerU。

### 书签清洗与补抓

1. 对 URL 去重并清洗。
2. 使用 httpx 异步抓取，并以超时结果过滤死链。
3. 使用 trafilatura 抽取正文，并拦截处于登录态、无法直接取得正文的页面。
4. 仍需补抓时，使用 Playwright 复用本机浏览器 Profile，按需补抓。

本地浏览器 Profile 只存在于运行机器上，不纳入本仓库。登录态拦截用于把需要登录的页面标出来；补抓不用于绕过登录或权限控制。

### 状态机与容错

每条资料计划处于下列四种状态之一：

| 状态 | 计划含义 |
| --- | --- |
| `pending` | 已接收，尚未处理完成 |
| `ok` | 处理成功 |
| `dead_link` | 确认为死链（含抓取超时） |
| `auth_required` | 页面需要登录，本次不取得正文 |

在此状态机上计划实现两件事：

- **断点续传**：处理中断后，从尚未完成的条目继续，而不是整批重来。
- **脏数据隔离**：无法可靠解析或抓取的数据与已成功数据分开存放，不混入可检索结果。

状态流转、续传和隔离都尚未实现。

## 自动化维护闭环（Devin Bot）

下面三项是计划中的维护闭环，暂称 Devin Bot。它们都还没有接入。本仓库没有机器人、定时任务、工作流或合并门禁，本次也不设置任何真实自动化。

- **异常解析死信队列自愈**：计划把解析失败的条目送入死信队列，再按规则重试或隔离。当前没有死信队列，也没有自愈逻辑。
- **定时依赖冲突巡检**：计划定时检查依赖是否冲突。当前没有巡检脚本，也没有定时调度。
- **PR 性能与 Golden Dataset 召回率门禁**：计划在后续 PR 上检查性能，并用 Golden Dataset 的召回率作为合并门禁。当前没有该门禁，也没有 Golden Dataset。
